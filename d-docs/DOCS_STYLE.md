# V 文档规范

目标：**简洁、高信息密度、易读、易懂。**

优先级：

```text
可读性 / 可理解性
        ↓
信息密度
        ↓
篇幅更短
```

不能为了“短”牺牲理解成本。

## 规则

| 项目 | 规范 |
|---|---|
| 正文语言 | 全部使用简体中文 |
| 路径语言 | 文件夹名、文件名只能使用 ASCII 安全字符 |
| 路径字符 | 仅允许 `A-Z a-z 0-9 . _ -` |
| 禁止路径 | 中文、法文重音字母及其他非 ASCII Unicode 字符不得进入路径 |
| 术语 | 通用技术词可保留英文，如 `runtime/provider/benchmark` |
| 结构 | 先结论，后细节；层级尽量少 |
| 压缩 | 优先表格、树状图、ASCII 图、公式 |
| 列表 | 用于并列事实/动作，避免长段重复 |
| 段落 | 一个段落只表达一个核心意思 |
| 重复 | 同一事实只保留一个权威位置，其他文档引用 |
| 状态 | 明确区分：已锁定 / 暂定 / 待验证 / 延后 |

## 路径规范

**路径必须只含 ASCII。正文可以且应当使用简体中文。**

```text
允许：
d-docs/DOCS_STYLE.md
d-docs/lore/naming-history.md
benchmarks/terminal-bench-2.1/

禁止：
d-docs/文档规范.md
d-docs/花絮/
d-docs/lore/命名史.md
d-docs/résumé.md
```

原因：避免 Unicode 路径在 shell、脚本、CI、跨平台文件系统和第三方工具中产生不必要的编码、转义或兼容性问题。

新增文件或目录时，先检查路径，再写内容。

## 表达选择

```text
关系/流程   → ASCII 图
层级/组成   → 树状图
横向比较   → 表格
任务/状态   → checklist
公式/指标   → 公式
解释原因   → 短段落
```

示例：

```text
差：
V 支持本地模型。V 也支持云端模型。本地模型和云端模型都会通过 provider 连接……

好：
Provider
├─ local LLM API
└─ cloud LLM API
```

## 写完后的检查

1. 新增或修改的路径是否只包含 `A-Z a-z 0-9 . _ -`？
2. 是否存在可以改成图/表的长段落？
3. 是否重复解释了同一个概念？
4. 是否把“已确定”和“推测/计划”混在一起？
5. 删除一句话后是否仍不损失信息？若是，删除。
6. 压缩后是否增加了阅读/理解成本？若是，恢复必要文字。
